00 / START HERE

What exactly is this project?

This is an academic research prototype — not a proposed replacement for Australia’s existing payment system and not an RBA product. It uses a permissioned ledger to make institutional roles, digital-money flows and compliance questions tangible.

Important contextAustralia already operates high-value real-time gross settlement through RITS. The useful question here is how tokenised wholesale markets might coordinate money, identity, permissions and monitoring.
01

CBDC

Digital central-bank money. In a wholesale model, access is limited to eligible financial-market participants.

02

Wholesale settlement

The final movement of value between institutions — different from a consumer card or banking-app payment.

03

Permissioned ledger

A network where organisations are known and access can be controlled, unlike a public permissionless cryptocurrency network.

01 / CHALLENGE

The question was not “can we put money on a blockchain?” It was where identity, compliance and institutional authority belong.

The prototype had to model multiple institutional actors, restrict what each could do, validate identity and KYC state, screen transaction behaviour and then hand an approved application request to a permissioned ledger. That made governance decisions visible as software behaviour instead of leaving them only in a report.

01

Settlement

Transactions needed a deterministic path from proposal to validation and commit.

02

Identity

Central bank, banks, regulator and customer roles required materially different permissions.

03

Compliance

Suspicious behaviour had to be evaluated before irreversible ledger submission.

04

Oversight

The regulator needed visibility without becoming a transaction-authorising participant.

The AML function worked.
The system did not.

06 / IDENTITY & ACCESS

Authentication moved from prototype credentials to enterprise identity.

The application migrated from a JWT prototype to Keycloak with OAuth 2.0 / OpenID Connect and group-based role mapping.

Identity was enforced twice: the interface controlled what users could see, while the API controlled what they could actually do.

Reproducibility became part of the product.

Containerisation reduced setup friction across Fabric-adjacent services and gave the team a repeatable way to run identity, API and UI components.

10 / OUTCOME & REFLECTION
WHAT WORKED

Frequent demos exposed real requirements.

Feedback changed the system: KYC controls, identity, deployment and monitoring became stronger because the team demonstrated real flows rather than only presenting architecture.

WHAT FAILED

Assumption-based integration testing.

The AML defect survived because the team validated the function without validating the complete transfer journey early enough.

WHAT I’D CHANGE

Design for production constraints earlier.

Start with enterprise identity, persistent encrypted storage, integration tests and institution-scale monitoring calibration from the beginning.

Prototype limitations

Local/development deployment · heuristic AML thresholds · prototype KYC storage · no production banking integration · no formal production security accreditation.
